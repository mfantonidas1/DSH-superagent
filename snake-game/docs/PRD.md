# 单机版贪食蛇游戏 PRD

- 版本：v1.0（MVP 定义稿）
- 作者：pm（ai-dev-team 流水线）
- 状态：待架构师评审
- 交付位置：GitHub 仓库 mfantonidas1/DSH-superagent 内 `snake-game/` 目录，随一个 PR 交付

## 1. 背景与目标

用户希望用 ai-dev-team 流水线开发一个「单机版贪食蛇」：单人、离线可玩、无后端、无账号，形态为纯前端网页游戏，浏览器打开即玩。目标用户为普通休闲玩家，界面语言为简体中文。

产品目标（可验证）：
1. 玩家打开页面后 ≤3 次交互（含点击「开始」）即可进入一局游戏。
2. 完整覆盖经典贪食蛇闭环：控制 → 吃食物 → 变长加分 → 加速 → 死亡 → 重开。
3. 全程零网络请求：断网状态下功能与有网时完全一致（最高分本地保存）。

## 2. 明确假设（信息不足处，不臆造事实）

- A1：「单机」按 Lead 上下文理解为纯前端网页游戏；不要求桌面安装包或 App。
- A2：桌面键盘为主要输入方式；移动端触摸为增强项（P1），不阻塞 MVP。
- A3：经典规则取「撞墙即死」（非穿墙模式）；穿墙/障碍物等变体不在本期范围。
- A4：无账号体系，最高分仅保存在本机浏览器（localStorage），不做跨设备同步。
- A5：下列数值为默认值，供测试验收使用；架构师/开发可在实现时微调，但需保持「随分数变快」的可感知性：
  - 棋盘 20×20 格；蛇初始长度 3 节，初始方向向右。
  - 初始速度 4 格/秒；每吃 5 个食物提速一档（+1 格/秒），上限 12 格/秒。
  - 每个食物 +10 分；食物随机生成于空白格，同一时刻场上仅 1 个食物。
- A6：页面可通过 `file://` 直接打开或任意静态托管访问，均须可玩（不得依赖构建后仍需服务端接口）。

## 3. 用户故事

- US-1：作为休闲玩家，我想打开网页就能用方向键开始玩贪食蛇，以便零门槛消磨时间。
- US-2：作为玩家，我想吃到食物后蛇变长、分数上涨、速度逐渐变快，以便获得挑战与成就感。
- US-3：作为玩家，我想撞墙或咬到自己后看到本局得分并能一键重开，以便快速再来一局。
- US-4：作为玩家，我想随时暂停/继续，以便被打断时不丢进度。
- US-5：作为老玩家，我想看到本机历史最高分，以便挑战自己的纪录。
- US-6：作为手机用户，我想通过滑动屏幕控制方向，以便没有键盘也能玩。（P1）

## 4. 功能需求

优先级定义：P0 = MVP 必须；P1 = 本期尽量交付；P2 = 明确延后。

### P0（MVP）

| 编号 | 需求 | 说明 |
|------|------|------|
| FR-01 | 开始界面与开局 | 打开页面显示中文标题、最高分、「开始游戏」按钮与操作说明；点击开始（或按回车/空格）生成初始蛇与首个食物并开局 |
| FR-02 | 键盘方向控制 | 方向键与 WASD 均可控制；禁止 180° 直接反向；同一移动节拍内多次按键只取最后一次有效方向，防止一帧内连转导致自撞 |
| FR-03 | 移动、吃食物、生长与计分 | 蛇按当前速度自动前进；蛇头到达食物格时：长度 +1、分数 +10、在空白格生成新食物 |
| FR-04 | 死亡判定与结束界面 | 蛇头越出棋盘边界或与自身任一节重合即死亡；显示「游戏结束」、本局得分、历史最高分与「重新开始」按钮；若破纪录给出中文提示 |
| FR-05 | 重新开始 | 结束界面点击「重新开始」（或按回车）立即以初始状态开新局，无需刷新页面 |
| FR-06 | 暂停/继续 | 游戏中按空格或 P 键、或点击暂停按钮可暂停；暂停时画面静止并显示「已暂停」遮罩；再次触发继续；暂停期间方向键不生效 |
| FR-07 | 实时计分显示 | 游戏区上方常显当前分数与最高分，吃食物后即时更新 |
| FR-08 | 最高分本地持久化 | 最高分写入 localStorage；刷新或关闭浏览器后仍在；存储不可用时游戏仍可玩（最高分退化为本次会话内有效） |
| FR-09 | 随进度加速 | 按 A5 规则每吃 5 个食物提速一档至上限；当前速度档位以「速度 xN」形式可见 |

### P1（本期尽量交付）

| 编号 | 需求 | 说明 |
|------|------|------|
| FR-10 | 移动端触摸滑动 | 在游戏区滑动（上/下/左/右）改变方向，规则同 FR-02；滑动不得触发页面滚动 |
| FR-11 | 移动端可玩布局 | 竖屏下棋盘自适应缩放不溢出；提供屏上「暂停/开始」按钮，使无键盘设备可完成完整闭环 |
| FR-12 | 失焦自动暂停 | 浏览器标签页切走或窗口失焦时自动暂停，回来后需手动继续 |

### P2（明确延后，本期不做）

- FR-13 音效与开关；FR-14 穿墙/障碍物等规则变体；FR-15 皮肤/暗色主题；FR-16 排行榜（需后端，违背单机定位，仅记录为远期）。

## 5. P0 验收标准（Given/When/Then）

- FR-01
  - Given 首次打开页面，When 页面加载完成，Then 显示中文标题、最高分（无记录时显示 0）、操作说明与「开始游戏」按钮。
  - Given 开始界面，When 点击「开始游戏」，Then 出现 20×20 棋盘、长度 3 且向右移动的蛇、1 个食物，分数为 0。
- FR-02
  - Given 蛇正在向右移动，When 按下 ↑ 或 W，Then 下一节拍蛇头向上移动一格。
  - Given 蛇正在向右移动，When 按下 ← 或 A，Then 方向保持向右（忽略 180° 反向）。
  - Given 蛇向右移动且本节拍未结算，When 在同一节拍内先按 ↑ 再按 ←，Then 仅生效 ↑，蛇不会因反向自撞而死。
- FR-03
  - Given 游戏中且分数为 S、蛇长为 L，When 蛇头进入食物所在格，Then 分数变为 S+10、蛇长变为 L+1，且新食物出现在非蛇身的空白格。
  - Given 游戏中，When 蛇头进入空白格，Then 蛇整体前移一格、长度与分数不变。
- FR-04
  - Given 蛇头位于最右列且向右移动，When 下一节拍结算，Then 判定死亡并显示结束界面（含本局得分、最高分、「重新开始」）。
  - Given 蛇长 ≥5 且蛇头即将进入自身某节所在格，When 该节拍结算，Then 判定死亡并显示结束界面。
  - Given 本局得分高于存储的最高分，When 死亡结算，Then 最高分更新为本局得分并显示破纪录中文提示。
- FR-05
  - Given 结束界面，When 点击「重新开始」，Then 立即开新局：蛇长 3、分数 0、速度回到初始档，最高分保留。
- FR-06
  - Given 游戏进行中，When 按空格（或 P、或点暂停按钮），Then 蛇与计时静止并显示「已暂停」；When 再次按空格，Then 从暂停时的状态继续。
  - Given 已暂停，When 按方向键，Then 方向不改变、游戏不恢复。
- FR-07
  - Given 游戏进行中，When 吃到 1 个食物，Then 界面上当前分数在同一画面帧内 +10，最高分区域不被遮挡。
- FR-08
  - Given 已产生最高分记录，When 刷新页面或关闭后重开，Then 开始界面显示该最高分。
  - Given 浏览器禁用/不支持 localStorage，When 打开并开始游戏，Then 游戏正常可玩，无报错弹窗，最高分在本次会话内仍正确更新。
- FR-09
  - Given 初始速度档（4 格/秒），When 累计吃到第 5 个食物，Then 速度提升为 5 格/秒且界面速度指示更新为对应档位。
  - Given 已达速度上限（12 格/秒），When 继续吃食物，Then 速度不再增加，计分与生长照常。

## 6. 非功能需求

- NFR-01 性能：桌面端渲染目标 60fps，逻辑节拍与渲染解耦；连续游玩 10 分钟无明显卡顿或内存持续增长；输入到方向生效延迟 ≤1 个移动节拍。
- NFR-02 兼容性：最新版 Chrome / Edge / Firefox / Safari 桌面端可完整游玩；iOS Safari 与 Android Chrome 移动端至少满足 P1 布局与触摸需求（若 P1 未交付，桌面端不受影响）。
- NFR-03 离线可用（硬约束）：运行时零网络请求——不得引用外部 CDN 字体/脚本/图片，不得有接口调用、埋点或账号逻辑；所有资源随 `snake-game/` 目录本地交付；断网与 `file://` 打开均可玩（见 A6）。
- NFR-04 数据与隐私：仅在本地存储最高分一个键值；不采集、不上传任何用户数据。
- NFR-05 语言与文案：全部界面文案为简体中文，无占位英文/乱码；按钮与提示用语义化中文（如「开始游戏」「已暂停」「重新开始」）。
- NFR-06 可测试性：核心规则（移动、反向拦截、碰撞、计分、提速）应可被自动化测试覆盖，不依赖真实键盘事件即可驱动逻辑。
- NFR-07 交付约束：代码与文档全部位于仓库 `snake-game/` 目录内，README 提供中文「如何运行」说明；不引入需要后端进程的依赖。

## 7. 范围外事项

- 多人对战、联网排行榜、账号/登录、云存档。
- 桌面安装包、小程序/App 打包、PWA 安装能力。
- 关卡编辑、障碍物/穿墙等规则变体、道具系统（P2 或远期）。
- 音效、主题皮肤、国际化多语言（本期仅简体中文）。
- 技术选型（框架、渲染方式、构建工具）由架构师决定，本 PRD 仅约束第 6 节硬性条件。

## 8. MVP 建议与风险

- MVP = 全部 P0（FR-01~FR-09）+ NFR-01/03/04/05/06/07；P1 视排期加入，FR-10/11 优先于 FR-12。
- 最大风险：输入时序缺陷（同一节拍多次按键、180° 反向拦截不严）导致「莫名自撞」，直接损害核心手感；要求 FR-02 的三条验收必须自动化覆盖。
- 次级风险：`file://` 场景下部分浏览器对本地资源/localStorage 的限制（见 A6、FR-08 降级条款），架构师需在选型时验证。
